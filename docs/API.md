# Tachyon-v100 の口（API）と既定の値

コードの註の「docs/API.md 3.6」などは、この文書の節の番号を指す。

## 2. 口
- OpenAI 互換: `POST /v1/chat/completions`（stream あり／なし・画像あり）、`GET /v1/models`、`GET /health`
- `chat_template_kwargs` で `enable_thinking`・`reasoning_effort`・`preserve_thinking` を依頼ごとに変えられる
- 文書の先計算: `POST/GET/DELETE /v1/documents`（3.7）。止める前の受け付け停止: `POST /admin/drain`
- 鍵は `--keys keys.json`（鍵の sha256 だけを書く。`src/server/auth.rs` の頭に形）。既定は 127.0.0.1 だけで待つ

## 3. 既定の値（モデルの既定。serve の既定は `src/bin/tachyon.rs` の SERVE_DEFAULTS で上書きできる）
| 項目 | 既定 | 理由 |
|---|---|---|
| Thinking | あり（reasoning_effort は medium をエンジン側で明示） | テンプレートの既定は xhigh（考えが最も長い）。受け付ける値は xhigh・medium・low だけ、それ以外は 400 |
| preserve_thinking | ふつうの会話はなし、道具（tools）がある依頼はあり | 8 回の会話で前の考えを残すと最後の依頼は 2.7 万トークン（78% が考え）、外すと 5,800。道具の手番で外すと次で読み直しが要る。依頼で明示されたらそれに従う |
| 文脈の長さ | 1 依頼 256K まで（モデルの素の上限） | |
| 出力の上限 | 既定 32K、最大 128K | Thinking で長くなる |
| 試料の取り方 | Thinking: temp 1.0・top_p 0.95・top_k 20／なし: temp 0.7・top_p 0.8・presence 1.5 | モデルカードの推奨 |

## 3.5 決めごと
- 上限を超えた依頼: 入力が上限を超えたら 400（切り詰めない）。出力が上限に達したら finish_reason=length
- 人数を超えたら待たせる（列に並べる）。列が長すぎるときだけ 429
- 画像: 1 枚あたりのトークンに上限。画像のトークンも文脈の長さに数える
- /health: 「読み込み中」と「準備完了」を分けて返す
- ログには誰が・いつ・何トークンかだけ残す。依頼の中身（文・画像）と鍵は残さない
- `/v1/models` の ID に重みの版（sha の先頭）を入れる
- 賢さの確かめ: 温度 0 で llama-server と突き合わせる。MTP は確かめてから受け取るので、温度 0 の答えは MTP なしと同じでなければならない

## 3.6 KV キャッシュと文頭の使い回し
- ページ化した KV: 普通の Attention 層の KV を 64 トークンの頁で持つ。頁の置き場は GPU → RAM の段（`src/kv.rs`）。GPU が足りなくなったら、しばらく使っていない会話の頁から RAM へ逃がす
- 文頭の使い回し（prefix caching）: 同じ文頭（システムの指示、会話の前の回、同じ資料）は計算し直さない
- 線形 Attention（Gated DeltaNet）の層は、KV の代わりに「そこまでの全部をまとめた状態」（27B で 1 人約 151MB）を持つ。途中の好きな所からは再開できないので、区切りの所で状態の写しを取る:
  ①システムの指示の終わり ②会話の各回の終わり ③道具の手番の終わり ④長い入力の一定の語数ごと ⑤2 回以上分かれた所。写しは RAM に置き、当たった回数と新しさで捨てる。KV の頁と状態の写しは組で使う
- **アカウントごとの持ち主**: 1 本の木に節ごとの持ち主（共有／アカウント X）を付け、探すときは「共有」と「自分のアカウント」の節だけをたどる
  - 同じアカウントの中は全部共有。`internal` の印の付いた鍵どうしは全部共有してよい
  - 外部のアカウントどうしでは共有しない（当たりの速さから「他の人が同じ文を送った」と推し量れてしまう＝KV 共有の時間差による漏れ）
  - アカウントごとに使える頁の枠を持ち、1 つのアカウントが他を追い出さないようにする

## 3.7 文書を先に計算して置いておく
- 長い文書（議事録など）は 1 問目の計算が重く、使い回せれば 2 問目からは RAG と同じくらい速い
- 口: `POST /v1/documents`（文書と、使うアカウント・テンプレートの条件）→ 文書の番号。会話の依頼にその番号を付けると文書の分は計算しない。`GET/DELETE /v1/documents/{id}`
- 置くもの: 普通の Attention 層の KV ＋ 文書の終わり（と一定の語数ごと）の線形 Attention の状態の写し
- 条件: 先頭が 1 トークンも違わないこと（システムの指示と文書を同じ並びで先頭、質問は後ろ）。reasoning_effort の xhigh・low はプロンプトの頭に 1 文足すので設定ごとに別の保存
- 持ち主: 外部のアカウントの文書はそのアカウントの中だけ。`internal` の文書は `internal` の鍵どうしで共有してよい

## 4.55 長い文脈
- 重いのは普通の Attention の層だけ（27B: 16 層・KV 4 ヘッド × 256、fp16 で 64KB/トークン）。線形 Attention の層は長さによらず 1 人一定
- 打つ手: KV を 8 ビットに詰める（頁ごとの係数）／KV の頁を RAM に段分けする（固定した RAM・zero-copy の写し）／前の回の考えを文脈から外す（preserve_thinking なし）／プレフィルを塊に分けて他の人のデコードと混ぜる・デコードの Attention を長さで分けて並べる（split-K）
